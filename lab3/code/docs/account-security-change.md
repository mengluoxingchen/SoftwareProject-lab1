# 0.9.4 账号密码与恢复码

变更编号：CR-006。来源：2026-11-14用户明确要求完善修改密码及忘记密码处理。新增REQ-022，原REQ-001至REQ-021保留。数据库由schema11迁移至schema12，旧用户密码、用户编号、账本、费用和还款不重建。

## 交互与规则

- 登录页增加“忘记密码”，登录后右上角增加“账号安全”，适用于所有已登录账号，不以账本角色授予额外账号权限。
- 修改密码需验证当前密码，并输入符合原8至32位规则的新密码两次。成功后使该账号全部会话失效，返回登录页；其他用户会话不受影响，业务数据保留。
- 新账号注册时产生128位随机恢复凭证，以8组四位十六进制字符展示。界面只展示当次明文，支持主动复制，60秒后若剪贴板仍是该码则清除。后台保存独立盐和PBKDF2摘要，不写共享账本日志。
- 已有账号登录后可验证当前密码生成恢复码；再次生成立即替换旧码。忘记密码时提交用户名、已保存恢复码、新密码及确认值；后台验证成功后原子更新口令、轮换恢复码、撤销全部会话并记录私有账号安全事件，返回新的恢复码但不自动登录。
- 未设置恢复码且忘记密码，或密码与恢复码同时遗失，无法自助恢复。没有只凭用户名、账本管理员身份或修改前端状态即可绕过验证的入口。
- 错误密码与恢复码验证分别限速，连续5次失败后该类操作等待30秒；密码重置失败不锁定普通登录。账号不存在、未配置恢复码、恢复码不正确使用相同恢复失败提示。连接中断不自动重放密码变更，提示先尝试新密码登录。

## 数据与实现

新增account_recovery及account_security_events。账号安全事件只记用户编号、动作和时间，无口令、恢复码和共享账本信息，并禁止更新/删除。身份恢复与账目输入副本RecoveryStore是两个不同机制，后者不保存账号恢复凭据。

核心代码为identity/account_security.cpp和ui/account_security_ui.cpp；注册流程在同一事务内创建用户与恢复码。schema12迁移只新增账号安全表；原schema11的expense_requests不会重复创建。以前更长的有效密码仍可作为当前密码验证，新密码采用当前注册规则。

## 验证范围

新增AccountSecurityTests七个后台场景：恢复凭据只返回一次及摘要存储、撤销本人会话并保留账目、恢复码单次使用与轮换、无效输入/越权/旧口令兼容、限速与普通登录独立、事务回滚，以及schema11持久化升级。新增UiSecurityTests一个原生Windows完整流程，验证错误当前密码、修改后登录、生成/复制恢复码、错误码提示、重置后正常登录及账本和90元支出保留。
